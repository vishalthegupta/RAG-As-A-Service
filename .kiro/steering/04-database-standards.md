# Database & Migration Standards

## SQLAlchemy Setup
- Use `AsyncSession` from `sqlalchemy.ext.asyncio` exclusively
- Connection pool: `pool_size=10`, `max_overflow=20`, `pool_pre_ping=True`
- `pool_pre_ping=True` is mandatory — prevents stale connections on restarts
- Session lifecycle managed via `get_db()` dependency — never create sessions manually in services

```python
# app/database.py — the only place engine is created
from sqlalchemy.ext.asyncio import create_async_engine, async_sessionmaker, AsyncSession

engine = create_async_engine(
    settings.DATABASE_URL,
    pool_size=10,
    max_overflow=20,
    pool_pre_ping=True,
    echo=settings.DEBUG,   # SQL logging in dev only
)

AsyncSessionLocal = async_sessionmaker(engine, expire_on_commit=False)
```

## Base Model
```python
# app/models/base.py — all models inherit from this
from sqlalchemy.orm import DeclarativeBase, mapped_column, Mapped
from sqlalchemy import DateTime, func
from uuid import UUID, uuid4

class Base(DeclarativeBase):
    pass

class TimestampMixin:
    created_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True), server_default=func.now(), nullable=False
    )
    updated_at: Mapped[datetime | None] = mapped_column(
        DateTime(timezone=True), onupdate=func.now(), nullable=True
    )
```
Every table model must inherit `Base` and `TimestampMixin`.

## Migrations (Alembic)
- Every schema change = a new Alembic migration. Never alter tables manually.
- Generate migrations: `alembic revision --autogenerate -m "description"`
- Always review autogenerated migrations before applying — Alembic misses some things (CHECK constraints, custom types)
- Migration descriptions must be meaningful: `add_chunk_count_to_documents` not `update_table`
- Migrations must be reversible — always implement `downgrade()`
- Run on app startup in non-prod: `alembic upgrade head` in entrypoint script
- In prod: run migrations as a separate step before deploying new app version

## Query Patterns
```python
# Fetch one or 404
async def get_document_or_404(db: AsyncSession, doc_id: UUID, user_id: UUID) -> Document:
    result = await db.execute(
        select(Document)
        .where(Document.id == doc_id, Document.user_id == user_id)
    )
    doc = result.scalar_one_or_none()
    if not doc:
        raise DocumentNotFoundError(f"Document {doc_id} not found")
    return doc

# List with pagination (always paginate lists)
async def list_documents(db: AsyncSession, user_id: UUID, skip: int = 0, limit: int = 50) -> list[Document]:
    result = await db.execute(
        select(Document)
        .where(Document.user_id == user_id)
        .order_by(Document.created_at.desc())
        .offset(skip)
        .limit(limit)
    )
    return result.scalars().all()
```

## Indexing Rules
- Every FK column must have an index
- Every column used in `WHERE` clauses must have an index
- Composite indexes for multi-column filters: `(user_id, status)`, `(session_id, created_at)`
- Define indexes in the model using `__table_args__`
- JSONB columns that are queried: add GIN index

## Transactions
- For multi-step writes (e.g., create Document + create ProcessingJob), wrap in a single transaction
- Use `async with db.begin():` for explicit transaction control
- If the Celery task fails after DB write, the DB write stays — design for idempotency

## Connection in Celery Tasks
- Celery tasks are sync — use a sync SQLAlchemy session, NOT the async one
- Create a separate `SyncSessionLocal` for Celery workers
- Never share the async session factory with Celery

```python
# app/database.py — sync engine for Celery
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker

sync_engine = create_engine(settings.SYNC_DATABASE_URL, pool_pre_ping=True)
SyncSessionLocal = sessionmaker(sync_engine)
```
